================================================================================
                SaveEats - ธีมและแนวทางการออกแบบ UI / UX
================================================================================
เอกสารนี้อธิบายว่าธีมของ SaveEats เป็นอย่างไร ทำไมถึงเลือกแบบนี้
และมีกฎอะไรบ้างที่ทุกคนต้องทำตามเพื่อให้แอปกับเว็บหน้าตาไปในทิศทางเดียวกัน


================================================================================
ส่วนที่ 1 : กฎสำคัญที่สุดของธีม
================================================================================

  *** ธีมของ SaveEats เก็บอยู่ 2 ไฟล์ ที่ต้องตรงกันเป๊ะเสมอ ***

      แอปมือถือ  ->  mobile/src/core/theme/colors.ts
      Admin Web  ->  admin-web/src/styles/theme.css

  ถ้าแก้สีที่ไฟล์หนึ่ง ต้องไปแก้อีกไฟล์ให้ตรงกันทันที
  ไม่งั้นแอปกับเว็บจะเป็นคนละสีกัน ดูเหมือนคนละระบบ

  กฎย่อย
  ------
  [ห้าม]  เขียนโค้ดสีตรง ๆ ในหน้าจอ  เช่น  color: '#16A34A'
  [ต้อง]  import จากธีมเสมอ         เช่น  color: theme.colors.primary

  [ห้าม]  ตั้งระยะห่างเป็นเลขมั่ว ๆ  เช่น  padding: 13
  [ต้อง]  ใช้จากธีม                 เช่น  padding: theme.spacing.md

  *** ตอนนี้ TypeScript ช่วยคุมให้แล้ว ***
  theme.colors, theme.spacing, theme.radius ประกาศเป็น as const
  ถ้าพิมพ์ชื่อผิด เช่น theme.colors.primry จะขึ้นเส้นแดงทันที
  และกด Ctrl+Space หลังจุด จะขึ้นรายการสีทั้งหมดให้เลือก

  เหตุผล : ถ้าวันหนึ่งอาจารย์บอกว่าอยากเปลี่ยนสีหลักเป็นสีอื่น
           ถ้าทำตามกฎ จะแก้ที่เดียว 2 ไฟล์ เสร็จภายใน 1 นาที
           ถ้าไม่ทำตามกฎ ต้องไล่แก้ทีละหน้าจอ 30 กว่าไฟล์


================================================================================
ส่วนที่ 2 : แนวคิดของธีม
================================================================================

  สีหลักคือ "เขียว"
  -----------------
      ความหมาย : อาหารที่ถูกช่วยไว้ ความสดใหม่ การรักษาสิ่งแวดล้อม
      ใช้กับ    : ปุ่มหลัก แถบเมนูที่เลือกอยู่ ไอคอน โลโก้ สถานะสำเร็จ

      เลือกเขียวเพราะ SaveEats เป็นเรื่องการลดขยะอาหาร
      คนเห็นสีเขียวจะนึกถึงความยั่งยืนโดยอัตโนมัติ

  สีรองคือ "ส้ม"
  --------------
      ความหมาย : ความอร่อย ความเร่งด่วน
      ใช้กับ    : ราคาที่ลดแล้ว ป้ายเปอร์เซ็นต์ส่วนลด เวลาที่เหลือ

      เลือกส้มเพราะเป็นสีที่กระตุ้นความอยากอาหารมากที่สุด
      และตัดกับเขียวได้ชัด ทำให้ราคาส่วนลดเด่นออกมาทันที

  สัดส่วนการใช้สี (หลัก 60-30-10)
  -------------------------------
      60%  สีพื้นหลังกลาง ๆ (เทาอ่อน ขาว)
      30%  สีเขียวหลัก
      10%  สีส้ม

      *** อย่าใช้เขียวเต็มจอ จะดูล้าตาและเห็นอะไรไม่เด่น ***

ส่วนที่ 4 : สีประจำสถานะ (ต้องใช้ให้ตรงกันทั้งระบบ)
================================================================================

  สถานะการจอง (reservations.status)
  ---------------------------------
      confirmed   จองสำเร็จ       พื้นฟ้าอ่อน  ตัวอักษรฟ้า
      waiting     รอรับอาหาร      พื้นเหลืองอ่อน ตัวอักษรน้ำตาลเข้ม
      completed   รับอาหารแล้ว    พื้นเขียวอ่อน ตัวอักษรเขียว
      expired     หมดอายุ         พื้นเทาอ่อน  ตัวอักษรเทา
      cancelled   ยกเลิก          พื้นแดงอ่อน  ตัวอักษรแดง

  สถานะร้าน (stores.status)
  -------------------------
      pending     รออนุมัติ       พื้นเหลืองอ่อน
      approved    อนุมัติแล้ว     พื้นเขียวอ่อน
      rejected    ไม่อนุมัติ      พื้นแดงอ่อน
      suspended   ถูกระงับ        พื้นเทาอ่อน

  ค่าพวกนี้เขียนไว้ให้แล้วที่
      mobile     : core/theme/colors.ts (reservationStatusColors, storeStatusColors)
      admin-web  : styles/theme.css (คลาส .badge-xxx)
      ข้อความไทย : shared/src/labels.ts (ใช้ร่วมกันทั้งแอปและเว็บ)

  *** ประกาศเป็น Record<ReservationStatus, StatusColor> ***
  แปลว่า ถ้าเพิ่มสถานะใหม่ใน shared/src/enums.ts แล้วลืมมาเพิ่มสีที่นี่
  TypeScript จะฟ้องทันทีว่า "ขาดสถานะ xxx" ไม่มีทางลืม

  วิธีใช้
      mobile     :  <StatusBadge status="pending" type="store" />
      admin-web  :  <StatusBadge status="pending" />

  *** อย่าเขียนสีสถานะเองในแต่ละหน้า ให้ใช้ StatusBadge เท่านั้น ***

ส่วนที่ 5 : ตัวหนังสือ
================================================================================

  ฟอนต์ที่ใช้ : Prompt
  -------------------
      เป็นฟอนต์ไทยฟรีจาก Google Fonts ที่อ่านง่ายที่สุดบนหน้าจอ
      รองรับทั้งภาษาไทยและอังกฤษในตัวเดียว น้ำหนักตัวอักษรครบ

      แอปมือถือ  : ต้องโหลดไฟล์ .ttf มาวางใน mobile/assets/fonts/
                   (ดูวิธีในไฟล์ 02 หัวข้อ "ปัญหาที่เจอบ่อย" ข้อ 7)
      Admin Web  : โหลดจาก Google Fonts CDN ผ่าน index.html แล้ว ไม่ต้องทำอะไร

  น้ำหนักที่ใช้
  -------------
      Regular  (400)   ตัวหนังสือทั่วไป
      Medium   (500)   label ป้ายสถานะ เมนูที่เลือกอยู่
      SemiBold (600)   หัวข้อรอง ปุ่ม
      Bold     (700)   หัวข้อใหญ่ ราคา

  ขนาดตัวหนังสือ
  --------------
      title        24px   หัวข้อหน้าจอ
      heading      18px   ชื่อร้าน ชื่ออาหาร หัวข้อการ์ด
      subheading   16px   หัวข้อย่อย
      body         15px   ตัวหนังสือทั่วไป
      bodyMuted    14px   คำอธิบาย
      caption      12px   เวลา ป้ายสถานะ ข้อความรอง
      price        20px   ราคาที่ลดแล้ว (ตัวหนา สีส้ม)
      priceStrike  14px   ราคาเดิม (ขีดฆ่า สีเทา)

  *** ห้ามใช้ขนาดเล็กกว่า 12px ***
  เพราะคนสายตาไม่ดีจะอ่านไม่ออกบนมือถือ

  *** ระยะห่างระหว่างบรรทัด (lineHeight) ตั้งไว้ที่ประมาณ 1.5 เท่าของขนาด ***
  ภาษาไทยมีสระบนล่าง ถ้าบรรทัดชิดเกินไปสระจะทับกัน

ส่วนที่ 7 : หลัก UX ที่ใช้ในโปรเจกต์นี้
================================================================================

--------------------------------------------------------------------------------
หลักที่ 1 : ทุกหน้าที่ดึงข้อมูล ต้องมีครบ 4 สถานะ
--------------------------------------------------------------------------------
      1. กำลังโหลด      -> แสดง LoadingView (วงกลมหมุน + ข้อความ)
      2. มีข้อมูล        -> แสดงข้อมูล
      3. ไม่มีข้อมูล     -> แสดง EmptyState (ไอคอน + คำอธิบาย + ปุ่มทำอะไรต่อ)
      4. เกิดข้อผิดพลาด  -> แสดงข้อความ error + ปุ่มลองใหม่

      *** ห้ามปล่อยหน้าจอขาวเปล่า ๆ เด็ดขาด ***
      ผู้ใช้จะไม่รู้ว่าแอปค้าง เน็ตหลุด หรือไม่มีข้อมูลจริง ๆ

      ดูตัวอย่างที่ HomeScreen.tsx ทำครบทั้ง 4 สถานะแล้ว

--------------------------------------------------------------------------------
หลักที่ 2 : ห้ามใช้ alert เด้งบอก error
--------------------------------------------------------------------------------
      [ผิด]  Alert.alert('Error', 'อีเมลไม่ถูกต้อง')
      [ถูก]  แสดงกล่องสีแดงในหน้า หรือข้อความใต้ช่องที่กรอกผิด

      เหตุผล : alert เด้งขวางทาง ต้องกดปิดก่อน
               และพอปิดแล้วผู้ใช้จำไม่ได้ว่า error คืออะไร

      ใช้ alert ได้เฉพาะกรณีเดียว : ถามยืนยันก่อนทำสิ่งที่ย้อนกลับไม่ได้
      เช่น "ต้องการออกจากระบบใช่หรือไม่"

--------------------------------------------------------------------------------
หลักที่ 3 : ตรวจฟอร์มตอนกดปุ่ม ไม่ใช่ตอนพิมพ์
--------------------------------------------------------------------------------
      ถ้าตรวจตอนพิมพ์ จะมี error เด้งใส่หน้าตั้งแต่พิมพ์ตัวแรก
      ซึ่งกวนใจมาก เพราะผู้ใช้ยังพิมพ์ไม่เสร็จด้วยซ้ำ

      วิธีที่ใช้ในโปรเจกต์นี้
          1. กดปุ่ม -> ตรวจทั้งฟอร์ม -> แสดง error ใต้ช่องที่ผิด
          2. ผู้ใช้แก้ที่ช่องไหน -> ลบ error ของช่องนั้นออก

--------------------------------------------------------------------------------
หลักที่ 4 : ปุ่มที่กำลังทำงานต้องกดซ้ำไม่ได้
--------------------------------------------------------------------------------
      *** สำคัญมากกับปุ่ม "จองอาหาร" ***
      ถ้ากดซ้ำได้ ลูกค้าจะจองซ้ำโดยไม่ตั้งใจ แล้วของหมดโดยเปล่าประโยชน์

      AppButton จัดการให้แล้ว แค่ส่ง loading={true} เข้าไป
      ปุ่มจะเปลี่ยนเป็นวงกลมหมุนและกดไม่ได้

--------------------------------------------------------------------------------
หลักที่ 5 : ห้ามใช้สีอย่างเดียวบอกความหมาย
--------------------------------------------------------------------------------
      คนตาบอดสีมีประมาณ 8% ของผู้ชายทั้งหมด
      ถ้าใช้แค่สีบอกสถานะ คนกลุ่มนี้จะแยกไม่ออก

      [ผิด]  ป้ายสีเขียว กับ ป้ายสีแดง เฉย ๆ
      [ถูก]  ป้ายสีเขียวเขียนว่า "อนุมัติแล้ว" ป้ายสีแดงเขียนว่า "ไม่อนุมัติ"

      StatusBadge มีข้อความกำกับเสมออยู่แล้ว

--------------------------------------------------------------------------------
หลักที่ 6 : ใช้ภาษาไทยที่คนทั่วไปเข้าใจ
--------------------------------------------------------------------------------
      [ผิด]  "Error 404: Resource not found"
      [ถูก]  "ไม่พบร้านค้านี้"

      [ผิด]  "Authentication failed"
      [ถูก]  "อีเมลหรือรหัสผ่านไม่ถูกต้อง"

      [ผิด]  "Insufficient quantity"
      [ถูก]  "ขออภัย อาหารเหลือไม่พอแล้ว"

      Backend เขียนข้อความ error เป็นภาษาไทยไว้หมดแล้ว
      ฝั่งแอปแค่เอา err.message มาแสดงตรง ๆ ได้เลย

--------------------------------------------------------------------------------
หลักที่ 7 : บอกให้ชัดว่าต้องทำอะไรต่อ
--------------------------------------------------------------------------------
      ตอนไม่มีข้อมูล อย่าเขียนแค่ "ไม่มีข้อมูล"
      ให้บอกด้วยว่าทำอะไรต่อได้

      [ธรรมดา]  "ไม่มีอาหาร"
      [ดีกว่า]  "ยังไม่มีอาหารในตอนนี้
                 ลองเปลี่ยนหมวดหมู่ หรือกลับมาดูใหม่ช่วงเย็น
                 ซึ่งเป็นเวลาที่ร้านลงขายเยอะที่สุด"
                 [ปุ่ม รีเฟรช]

--------------------------------------------------------------------------------
หลักที่ 8 : เน้นสิ่งที่สำคัญที่สุดของแต่ละหน้าจอ
--------------------------------------------------------------------------------
      1 หน้าจอ ควรมีปุ่มหลักที่เด่นที่สุดแค่ 1 ปุ่ม

      หน้า Feed              -> ปุ่ม "จองอาหาร" บนการ์ด
      หน้ายืนยันการจอง       -> ปุ่ม "ยืนยันการจอง"
      หน้าร้านค้า            -> ปุ่มสแกน QR (ทำเป็นวงกลมเด่นกลางแถบเมนูล่าง)
      หน้าแดชบอร์ด Admin     -> การ์ด "ร้านรออนุมัติ" (สีเหลืองสะดุดตา)

      ถ้ามีปุ่มเด่นหลายปุ่ม ผู้ใช้จะลังเลว่าควรกดอันไหน

--------------------------------------------------------------------------------
หลักที่ 9 : สร้างความเร่งด่วนอย่างพอดี ไม่กดดันเกินไป
--------------------------------------------------------------------------------
      SaveEats ขายของที่มีเวลาจำกัด จึงต้องบอกความเร่งด่วน

      สิ่งที่ทำ

          ข้อความแบบ "รีบเลย ใกล้หมดแล้ว!!!"

ส่วนที่ 9 : หน้าตาของ FoodPostCard (ชิ้นที่สำคัญที่สุด)
================================================================================

    +--------------------------------------+
    |                                      |
    |  [ลด 42%]         [รูปอาหาร]  [เหลือ 5 ชุด]|
    |                                      |
    +--------------------------------------+
    |  ร้าน ครัวคุณแม่   4.5 ดาว     1.2 กม. |
    |                                      |
    |  ข้าวกะเพราหมูสับไข่ดาว               |
    |  กะเพราเหลือจากมื้อเที่ยง...           |
    |                                      |
    |  รับได้ 17:00 - 20:00    อีก 2 ชม.    |
    |  ------------------------------------ |
    |  60 บาท  35 บาท        [ จองอาหาร ]  |
    +--------------------------------------+

  เหตุผลของการจัดวางแต่ละส่วน
  ---------------------------
      ป้ายส่วนลดอยู่มุมซ้ายบน   -> ตำแหน่งที่สายตาคนมองก่อนเป็นอันดับแรก
      จำนวนคงเหลืออยู่มุมขวาบน  -> สร้างความรู้สึกว่าต้องรีบ
      ชื่อร้านอยู่บนชื่ออาหาร   -> คนเลือกจากความน่าเชื่อถือของร้านก่อน
      ราคาเดิมขีดฆ่าข้างราคาใหม่ -> เห็นความคุ้มได้ทันทีโดยไม่ต้องคิดเลข
      ปุ่มจองอยู่มุมขวาล่าง     -> ตำแหน่งที่นิ้วโป้งเอื้อมถึงง่ายที่สุด
      เวลาที่เหลือเป็นสีส้ม     -> เร่งด่วนแต่ไม่ก้าวร้าว
