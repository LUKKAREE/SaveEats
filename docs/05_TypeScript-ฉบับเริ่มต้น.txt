================================================================================
        SaveEats - TypeScript ฉบับเริ่มต้น (อ่านก่อนเขียนโค้ดบรรทัดแรก)
================================================================================
เอกสารนี้เขียนให้คนที่เคยเขียนแต่ JavaScript มาก่อน
ไม่ต้องมีพื้นฐาน TypeScript มาก่อนเลย อ่านจบแล้วเริ่มเขียนได้ทันที

ใช้เวลาอ่าน : ประมาณ 15 นาที


================================================================================
ส่วนที่ 1 : ทำไมทีมเปลี่ยนมาใช้ TypeScript
================================================================================

เดิมทีมเลือก JavaScript เพราะ "เริ่มง่ายกว่า"
แต่มีเงื่อนไขว่าต้องชดเชย 2 อย่าง (ดูกฎข้อ 5 ในแผนงานเดิม)
      1. เขียน JSDoc กำกับทุก Model
      2. ตั้งชื่อ field ให้ตรงกันเป๊ะทั้ง 3 ฝั่ง

ปัญหาคือ ทั้งสองข้อนี้ต้องอาศัย "ความจำและวินัยของคน"
พอทำงาน 3 คน แก้โค้ดคนละที่คนละเวลา จะพลาดแน่นอน

ตัวอย่างบั๊กที่เกิดขึ้นจริงบ่อยมาก
---------------------------------
      // ฐานข้อมูลเก็บคอลัมน์ชื่อ discount_price
      // แต่คนเขียนแอปจำผิดเป็น discountPrice

      <Text>{post.discountPrice} บาท</Text>

      JavaScript : ไม่มีใครเตือน แอปแสดงคำว่า "undefined บาท"
                   ต้องเปิดแอปแล้วเห็นเองถึงจะรู้ และหาสาเหตุนาน

      TypeScript : ขึ้นเส้นแดงใต้คำนั้นทันทีตอนพิมพ์
                   พร้อมบอกว่า "ไม่มี field ชื่อนี้ คุณหมายถึง discount_price ใช่ไหม"

สิ่งที่ได้เพิ่มมา
----------------
  1. พิมพ์ชื่อ field ผิด -> รู้ทันที ไม่ต้องรอเปิดแอป
  2. ลืมเช็คค่าที่อาจเป็น null -> ฟ้องทันที (บั๊กยอดฮิตอันดับ 1)
  3. ส่ง parameter ไม่ครบตอนเปลี่ยนหน้า -> ฟ้องทันที
  4. autocomplete ใน VS Code แม่นยำมาก กด Ctrl+Space แล้วขึ้นทุก field ที่มีจริง
  5. แก้ชื่อคอลัมน์ในฐานข้อมูล -> TypeScript ไล่ชี้ให้เองว่าต้องตามไปแก้ที่ไหนบ้าง

สิ่งที่เสียไป
-------------
  1. ต้องพิมพ์เพิ่มนิดหน่อย (ระบุชนิดข้อมูล)
  2. ตอนแรกจะเจอเส้นแดงเยอะ รู้สึกน่ารำคาญ

  *** แต่เส้นแดงพวกนั้นคือบั๊กที่จะเกิดขึ้นจริงในอนาคต ***
  *** เจอตอนนี้ดีกว่าเจอตอนนำเสนอ ***

ส่วนที่ 2 : สิ่งที่ต้องรู้แค่ 7 อย่าง
================================================================================

--------------------------------------------------------------------------------
1) การบอกชนิดของตัวแปร  ใช้เครื่องหมาย :
--------------------------------------------------------------------------------
      let name: string = 'สมชาย';
      let price: number = 35;
      let isActive: boolean = true;

  ส่วนใหญ่ไม่ต้องเขียนก็ได้ เพราะ TypeScript เดาให้เอง
      let name = 'สมชาย';        // รู้เองว่าเป็น string

  ที่ต้องเขียนคือตอนประกาศ parameter ของฟังก์ชัน
      function formatPrice(value: number): string {
        return value + ' บาท';
      }
                    ^ ชนิดของ parameter    ^ ชนิดของค่าที่คืน

--------------------------------------------------------------------------------
2) interface  =  แบบแปลนของ object
--------------------------------------------------------------------------------
      interface Food {
        food_id: number;
        name: string;
        description: string | null;   // เป็น string หรือ null ก็ได้
        image?: string;               // มีหรือไม่มีก็ได้ (เครื่องหมาย ?)
      }

  พอประกาศแล้ว เอาไปใช้เป็นชนิดได้เลย
      const food: Food = { food_id: 1, name: 'ข้าวกะเพรา', description: null };

  ของ SaveEats ประกาศไว้หมดแล้วที่  shared/src/entities.ts
  ไม่ต้องเขียนเอง แค่ import มาใช้

--------------------------------------------------------------------------------
3) union type  =  "เป็นอย่างใดอย่างหนึ่ง"  ใช้เครื่องหมาย |
--------------------------------------------------------------------------------
      type StoreStatus = 'pending' | 'approved' | 'rejected' | 'suspended';

  แปลว่า ตัวแปรชนิดนี้ใส่ได้แค่ 4 คำนี้เท่านั้น
      let status: StoreStatus = 'approved';   // ผ่าน
      let status: StoreStatus = 'approve';    // ฟ้องทันที (สะกดผิด)

  *** นี่คือของที่มีประโยชน์ที่สุดในโปรเจกต์นี้ ***
  เพราะสถานะทั้งหมดของ SaveEats สะกดผิดไม่ได้เลย

  string | null คือ "เป็นข้อความ หรือเป็น null"
  ซึ่งเจอบ่อยมาก เพราะคอลัมน์ในฐานข้อมูลหลายตัวเป็น NULL ได้

--------------------------------------------------------------------------------
4) การจัดการค่าที่อาจเป็น null   *** สำคัญที่สุด ***
--------------------------------------------------------------------------------
      const store = await storeModel.findById(5);
      // ชนิดของ store คือ  Store | null   (เพราะอาจหาไม่เจอ)

      console.log(store.store_name);
                  ^^^^^ ฟ้องว่า "store อาจเป็น null"

  วิธีแก้ที่ถูกต้อง : เช็คก่อนใช้
      if (!store) {
        throw ApiError.notFound('ไม่พบร้านนี้');
      }
      console.log(store.store_name);   // ตรงนี้ TypeScript มั่นใจแล้วว่าไม่ null

  ตัวช่วยที่ใช้บ่อย
      value ?? 'ค่าสำรอง'      ถ้า value เป็น null หรือ undefined ให้ใช้ค่าสำรอง
      obj?.field               ถ้า obj เป็น null จะได้ undefined แทนที่จะพัง
      rows[0] ?? null          อ่านสมาชิกตัวแรกแบบปลอดภัย

  *** ห้ามใช้เครื่องหมาย ! เพื่อปิดปาก TypeScript ***
      console.log(store!.store_name);   // <- อย่าทำแบบนี้

  เพราะ ! แปลว่า "เชื่อฉันเถอะ มันไม่ null หรอก"
  ถ้าเราคิดผิด โปรแกรมจะพังตอนรันจริง ซึ่งคือปัญหาเดิมของ JavaScript เป๊ะ ๆ

--------------------------------------------------------------------------------
5) import type
--------------------------------------------------------------------------------
      import type { Food, Store } from '@shared/index';   // เอามาแค่ "ชนิด"
      import { UserRole } from '@shared/index';           // เอามาใช้จริงตอนรัน

  ถ้าเอามาเพื่อบอกชนิดอย่างเดียว ให้ใส่คำว่า type ด้วย
  จะช่วยให้ตัวแอปเบาลง เพราะตอน build จะตัดบรรทัดนั้นทิ้ง

--------------------------------------------------------------------------------
6) unknown  ในบล็อก catch
--------------------------------------------------------------------------------
      try {
        await something();
      } catch (err) {
        console.log(err.message);   // <- ฟ้อง เพราะ err เป็นชนิด unknown
      }

  เหตุผล : JavaScript โยนอะไรออกมาก็ได้ ไม่จำเป็นต้องเป็น Error

  ในโปรเจกต์นี้เตรียมตัวช่วยไว้แล้ว
      import { errorMessage } from '../core/services/apiClient';   // ฝั่งแอปและเว็บ

      catch (err) {
        setError(errorMessage(err));   // ได้ข้อความภาษาไทยพร้อมแสดงเลย
      }

--------------------------------------------------------------------------------
7) generic  =  ชนิดที่ยืดหยุ่นได้  ใช้วงเล็บ < >
--------------------------------------------------------------------------------
  เห็นบ่อยที่สุดตอนเรียก API

      const res = await apiGet<ApiResponse<FeedItem>>('/posts/1');
      res.data.food_name       // <- TypeScript รู้เลยว่ามี field นี้

  แปลว่า "ยิง GET แล้วจะได้ ApiResponse ที่ข้างในเป็น FeedItem"

  ไม่ต้องเขียน generic เองบ่อย ๆ แค่รู้ว่าอ่านยังไงก็พอ

ส่วนที่ 3 : โครงสร้าง type ของ SaveEats
================================================================================

ทั้งหมดอยู่ที่  shared/src/  แบ่งเป็น 5 ไฟล์

  enums.ts      ชุดตัวเลือกที่สะกดผิดไม่ได้
                UserRole, StoreStatus, PostStatus, ReservationStatus,
                BehaviorStatus, NotificationType, ReportStatus, FeedSort

  entities.ts   หน้าตาข้อมูลของแต่ละตาราง
                User, Store, Food, Post, Reservation, Review,
                AppNotification, BehaviorScore, Report, Category
                *** ชื่อ field ตรงกับคอลัมน์ใน schema.sql เป๊ะ ***

  dto.ts        หน้าตาข้อมูลที่ "ส่งเข้า" API
                RegisterRequest, LoginRequest, CreateFoodRequest,
                CreatePostRequest, CreateReservationRequest, FeedQuery, ...

  api.ts        หน้าตาข้อมูลที่ API "ส่งกลับ"
                ApiResponse<T>, PaginatedResponse<T>, AuthPayload,
                FeedItem, ReservationDetail, DashboardStats, ...

  labels.ts     ข้อความภาษาไทยของแต่ละสถานะ
                RESERVATION_STATUS_LABEL, STORE_STATUS_LABEL, ...
                *** ทำให้แอปกับเว็บใช้คำเดียวกันเสมอ ***

วิธี import (เหมือนกันทั้ง 3 โปรเจกต์)
--------------------------------------
      import type { Post, Reservation, Store } from '@shared/index';
      import { ReservationStatus, RESERVATION_STATUS_LABEL } from '@shared/index';

@shared คือทางลัดที่ตั้งไว้แล้ว ไม่ต้องเขียน '../../../../shared/src/index'

ส่วนที่ 4 : ทำไมชื่อ field ถึงเป็น snake_case
================================================================================

จะสังเกตว่าใน entities.ts ใช้ชื่อแบบ  discount_price  ไม่ใช่  discountPrice

เหตุผล : เพราะเป็นชื่อคอลัมน์ในฐานข้อมูลตรง ๆ

      ฐานข้อมูล  discount_price
      Backend    post.discount_price
      Mobile     post.discount_price

ถ้าไปแปลงเป็น camelCase กลางทาง จะต้องมีโค้ดแปลงชื่อเพิ่ม
และเป็นจุดที่พลาดได้อีก 1 จุด

*** แต่ข้อมูลที่ "ส่งเข้า" API (dto.ts) ใช้ camelCase ***
      { foodId: 1, discountPrice: 35, pickupStart: '...' }

เพราะเป็นข้อมูลที่แอปสร้างขึ้นเอง ไม่ได้มาจากฐานข้อมูลโดยตรง
Backend จะแปลงให้เองตอนเขียนลงฐานข้อมูล


================================================================================
ส่วนที่ 5 : ตั้งค่าความเข้มงวดไว้ระดับไหน
================================================================================

ทั้ง 3 โปรเจกต์เปิด strict เต็มที่ (ดูใน tsconfig.json)

  strict                    เปิดการตรวจเข้ม 8 อย่างพร้อมกัน
                            ที่สำคัญคือ strictNullChecks (เช็ค null ให้)
                            และ noImplicitAny (ห้ามปล่อยชนิดลอย ๆ)

  noUncheckedIndexedAccess  ทำให้ rows[0] มีชนิดเป็น T | undefined
                            บังคับให้เช็คก่อนใช้ กันบั๊ก "อ่านค่าจากของที่ไม่มี"

  noUnusedLocals            ตัวแปรที่ประกาศแล้วไม่ได้ใช้ จะฟ้อง
  noUnusedParameters        parameter ที่ไม่ได้ใช้ จะฟ้อง
                            (ถ้าตั้งใจไม่ใช้จริง ให้ใส่ _ นำหน้าชื่อ เช่น _req)

  noImplicitReturns         ฟังก์ชันที่บางเส้นทางไม่ return จะฟ้อง

*** ถ้ารู้สึกว่าเข้มเกินไป อย่าเพิ่งปิด ***
ลองแก้ตามที่มันบอกก่อน ส่วนใหญ่จะพบว่ามันชี้บั๊กจริง
ถ้าจะปรับจริง ๆ ให้คุยกันทั้งทีมแล้วแก้ tsconfig.json ทั้ง 3 ที่ให้ตรงกัน

ส่วนที่ 7 : ปัญหาที่มือใหม่เจอบ่อย
================================================================================

--------------------------------------------------------------------------------
ปัญหา : Property 'xxx' does not exist on type 'yyy'
--------------------------------------------------------------------------------
  แปลว่า : พิมพ์ชื่อ field ผิด หรือ field นั้นไม่มีอยู่จริง

  วิธีแก้ : กด Ctrl+Space หลังจุด แล้วดูว่ามี field อะไรให้เลือกบ้าง
            หรือกด Ctrl (Cmd บน Mac) แล้วคลิกที่ชื่อชนิด เพื่อกระโดดไปดูของจริง

--------------------------------------------------------------------------------
ปัญหา : Object is possibly 'null' หรือ 'undefined'
--------------------------------------------------------------------------------
  แปลว่า : ค่านี้อาจไม่มี ต้องเช็คก่อนใช้

  วิธีแก้ :
      if (!store) return;              // ออกไปก่อนถ้าไม่มี
      const name = store?.store_name;  // อ่านแบบปลอดภัย
      const name = store?.store_name ?? 'ไม่ทราบชื่อ';  // มีค่าสำรอง

--------------------------------------------------------------------------------
ปัญหา : Type 'string' is not assignable to type '"pending" | "approved" | ...'
--------------------------------------------------------------------------------
  แปลว่า : ค่าที่ส่งมาเป็นข้อความอะไรก็ได้ แต่ช่องนี้รับได้แค่ค่าที่กำหนดไว้

  มักเกิดตอนอ่านค่าจาก req.query ซึ่งเป็นข้อความอะไรก็ได้
  วิธีแก้ที่ใช้ในโปรเจกต์นี้ : เขียนฟังก์ชันแปลงค่าที่ตรวจให้ด้วย
  ดูตัวอย่างที่ parseStoreStatus() ใน backend/src/controllers/adminController.ts

--------------------------------------------------------------------------------
ปัญหา : Cannot find module '@shared/index'
--------------------------------------------------------------------------------
  แปลว่า : ทางลัด @shared ยังตั้งไม่ครบ

  ต้องตั้ง 2 ที่ (ตั้งอันเดียวไม่พอ)
      backend    : tsconfig.json ตรง paths
      admin-web  : tsconfig.json ตรง paths + vite.config.ts ตรง resolve.alias
      mobile     : tsconfig.json ตรง paths + babel.config.js ตรง alias
                   + metro.config.js ตรง watchFolders

  ถ้าแก้ไฟล์พวกนี้แล้วยังไม่หาย ให้ปิด expo แล้วรันใหม่แบบล้าง cache
      npx expo start -c

--------------------------------------------------------------------------------
ปัญหา : 'xxx' is declared but its value is never read
--------------------------------------------------------------------------------
  แปลว่า : ประกาศตัวแปรหรือ import มาแล้วไม่ได้ใช้

  วิธีแก้ : ลบทิ้ง หรือถ้าเป็น parameter ที่จำเป็นต้องมีแต่ไม่ได้ใช้
            ให้ใส่ _ นำหน้าชื่อ เช่น  function handler(_req, res) { ... }


================================================================================
ส่วนที่ 8 : เวลาจะแก้ฐานข้อมูล ต้องตามไปแก้ที่ไหนบ้าง
================================================================================

สมมติจะเพิ่มคอลัมน์ใหม่ชื่อ  is_halal  ในตาราง foods

  ขั้น 1  database/schema.sql
          เพิ่มบรรทัด  is_halal TINYINT(1) NOT NULL DEFAULT 0,
          แล้ว Import เข้า phpMyAdmin ใหม่

  ขั้น 2  shared/src/entities.ts
          เพิ่ม  is_halal: number;  ใน interface Food

  ขั้น 3  รัน npm run typecheck ในทั้ง 3 โฟลเดอร์
          TypeScript จะไล่บอกเองว่ามีที่ไหนต้องแก้เพิ่ม
          เช่น ตอน INSERT ใน foodModel.ts

  ขั้น 4  แก้ตามที่มันบอกจนหมด error

*** จุดสำคัญคือขั้นที่ 3 ***
สมัยใช้ JavaScript ต้องไล่หาเองว่าลืมแก้ตรงไหน
ตอนนี้ให้ TypeScript ไล่ให้ ไม่มีทางตกหล่น
