1.1  ตรวจว่าระบบพร้อม

1.2  *** สำคัญมาก : เลื่อนเวลาข้อมูลทดลองก่อนทดสอบทุกครั้ง ***
--------------------------------------------------------------
  ข้อมูลใน seed.sql ตั้งเวลารับอาหารไว้ 17:00-20:00 ของวันที่ Import
  ถ้าคุณทดสอบตอนกลางคืน หรือ Import ไว้เมื่อวาน
  *** Feed จะว่างเปล่า เพราะระบบกรองโพสต์ที่เลยเวลารับออกหมด ***

  วิธีแก้ (ใช้เวลา 10 วินาที)
      phpMyAdmin -> เลือก saveeats -> แท็บ Import
      -> เลือกไฟล์  database/refresh_time.sql  -> Go

  ไฟล์นี้เลื่อนเวลารับอาหารให้เริ่มจากตอนนี้ไปอีก 6 ชั่วโมง
  ไม่ลบข้อมูล ใช้ซ้ำได้เรื่อย ๆ

  [ ] รัน refresh_time.sql แล้ว

ส่วนที่ 2 : รอบ A - ทดสอบ Backend ด้วย Thunder Client
================================================================================
ทำได้เลยตอนนี้ ไม่ต้องรอหน้าจอ
ติดตั้ง Extension "Thunder Client" ใน VS Code แล้วกดไอคอนรูปสายฟ้าทางซ้าย

--------------------------------------------------------------------------------
A1  เข้าสู่ระบบและเอา Token
--------------------------------------------------------------------------------
  [ ] POST http://localhost:3000/api/auth/login
      Body (JSON) : { "email": "customer1@test.com", "password": "Test@1234" }

      ผลที่ต้องได้ : 200 และมี data.token
      *** คัดลอก token เก็บไว้ จะใช้ทุกข้อถัดไป ***

      ตรวจเพิ่ม
      [ ] ใน data.user ต้อง **ไม่มี** field ชื่อ password
      [ ] data.user.role = "customer"

  [ ] ทำซ้ำกับ seller1@test.com  -> เก็บ token ของร้านไว้
  [ ] ทำซ้ำกับ admin@saveeats.com -> เก็บ token ของ admin ไว้

  วิธีใส่ token ในคำขอถัดไป
      แท็บ Headers -> เพิ่ม
          Authorization : Bearer <วาง token ที่คัดลอกมา>

--------------------------------------------------------------------------------
A2  ดู Feed
--------------------------------------------------------------------------------
  [ ] GET http://localhost:3000/api/posts
      ไม่ต้องใส่ token ก็ได้ (Feed เปิดให้คนยังไม่ login ดูได้)

      ผลที่ต้องได้
      [ ] pagination.total = 4
      [ ] ไม่มีโพสต์ที่ 5 (ขายหมดแล้ว)
      [ ] แต่ละรายการมี food_name, store_name, normal_price, discount_price ครบ

  [ ] GET /api/posts?categoryId=2      -> ได้เฉพาะเบเกอรี่ (โพสต์ 3)
  [ ] GET /api/posts?maxPrice=30       -> ได้เฉพาะที่ราคา <= 30 (โพสต์ 3 และ 4)
  [ ] GET /api/posts?sort=price_asc    -> เรียงราคาจากน้อยไปมาก
  [ ] GET /api/posts?search=กะเพรา      -> ได้โพสต์ 1

--------------------------------------------------------------------------------
A3  ร้านใกล้เคียง (ทดสอบการคำนวณระยะทาง)
--------------------------------------------------------------------------------
  [ ] GET /api/stores/nearby?lat=13.7795&lng=100.5410&radius=5

      ผลที่ต้องได้
      [ ] ได้ 3 ร้าน (ร้านที่ 4 ไม่ขึ้นเพราะยังไม่อนุมัติ)
      [ ] ร้านครัวคุณแม่มี distance_km ใกล้ 0 (เพราะใช้พิกัดร้านนี้ค้นหา)
      [ ] เรียงจากใกล้ไปไกล

  [ ] GET /api/stores/nearby?lat=13.7795&lng=100.5410&radius=1
      -> ได้ร้านน้อยลง (รัศมีแคบลง)

  [ ] GET /api/stores/nearby       (ไม่ส่ง lat lng)
      -> ต้องได้ 400 พร้อมข้อความ "กรุณาส่งพิกัด lat และ lng มาด้วย"

--------------------------------------------------------------------------------
A4  จองอาหาร  *** หัวใจของระบบ ***
--------------------------------------------------------------------------------
  ใช้ token ของ customer2@test.com

  [ ] POST /api/reservations
      Body : { "postId": 2, "quantity": 1 }

      ผลที่ต้องได้
      [ ] 201 Created
      [ ] data.reservation_code เป็นตัวเลข 4 หลัก
      [ ] data.qr_payload ขึ้นต้นด้วย "SAVEEATS:"
      [ ] data.status = "confirmed"
      [ ] data.total_price = 35

      *** จดค่า reservation_code และ qr_payload ไว้ ใช้ในข้อ A5 ***

  [ ] เปิด phpMyAdmin ดูตาราง posts แถวที่ 2
      [ ] quantity_left ลดจาก 5 เหลือ 4

  [ ] เปิดตาราง notifications
      [ ] มีแจ้งเตือนใหม่ 2 อัน (ของลูกค้า 1 อัน ของร้าน 1 อัน)

--------------------------------------------------------------------------------
A5  ร้านยืนยันการรับอาหาร  *** กฎเหล็กข้อ 4 ***
--------------------------------------------------------------------------------
  ใช้ token ของ seller1@test.com (เจ้าของร้านครัวคุณแม่)

  [ ] POST /api/reservations/verify
      Body : { "qrPayload": "<วาง qr_payload จากข้อ A4>" }

      ผลที่ต้องได้
      [ ] 200 และ data.status = "completed"

  [ ] ยิงซ้ำอีกครั้งด้วย qrPayload เดิม
      [ ] ต้องได้ 409 พร้อมข้อความ "การจองนี้ถูกใช้รับอาหารไปแล้ว"
          *** ข้อนี้สำคัญมาก พิสูจน์ว่า QR ใช้ซ้ำไม่ได้ ***

  [ ] ทดสอบกรอกรหัส 4 หลักแทน
      สร้างการจองใหม่ก่อน (ทำข้อ A4 ซ้ำ) แล้วยิง
      POST /api/reservations/verify
      Body : { "code": "<รหัส 4 หลักที่ได้>" }
      [ ] ต้องได้ 200 และ status = completed

  [ ] ดูตาราง behavior_scores ของร้าน 1
      [ ] score เพิ่มขึ้น (ส่งมอบสำเร็จได้ +1)
  [ ] ดูตาราง behavior_logs
      [ ] มีแถวใหม่บันทึกว่า "ส่งมอบอาหารสำเร็จ 1 รายการ"

--------------------------------------------------------------------------------
A6  เขียนรีวิว
--------------------------------------------------------------------------------
  ใช้ token ของลูกค้าที่เพิ่งรับอาหารในข้อ A5

  [ ] POST /api/reviews
      Body : { "reservationId": <id จากข้อ A4>, "rating": 5, "comment": "อร่อยมาก" }
      [ ] ต้องได้ 201

  [ ] ยิงซ้ำด้วย reservationId เดิม
      [ ] ต้องได้ 409 "คุณรีวิวการจองนี้ไปแล้ว"

  [ ] ดูตาราง stores ร้านที่ 1
      [ ] rating และ review_count เปลี่ยนไป (ระบบคำนวณใหม่ให้อัตโนมัติ)

--------------------------------------------------------------------------------
A7  งานของ Admin
--------------------------------------------------------------------------------
  ใช้ token ของ admin@saveeats.com

  [ ] GET /api/admin/dashboard
      [ ] pendingStores = 1
      [ ] customers = 3
      [ ] sellers = 4

  [ ] GET /api/admin/stores/pending

  [ ] GET /api/admin/dashboard อีกครั้ง
      [ ] pendingStores เหลือ 0

  [ ] E7  login เป็น customer3 แล้วลองดูการจองของ customer1

          -> ต้องได้ 403 "คุณไม่มีสิทธิ์ดูการจองนี้"

  [ ] E8  ลอง login ด้วยบัญชี admin ในแอปมือถือ

ส่วนที่ 9 : ข้อจำกัดที่รู้อยู่แล้ว (ไม่ใช่บั๊ก)

เขียนไว้เพื่อไม่ให้เสียเวลาไล่หาสาเหตุ

  1. โพสต์หายจาก Feed หลัง 20:00 น.
     เพราะข้อมูลทดลองตั้งเวลารับไว้ถึง 20:00 ของวันที่ Import
     -> แก้ด้วยการรัน database/refresh_time.sql

  2. แผนที่ขึ้นเป็นสีเทา
     ยังไม่ได้ใส่ Google Maps API Key ในไฟล์ mobile/.env
     -> ดูขั้นตอนขอคีย์ในไฟล์ 02_วิธีติดตั้งและรัน.txt ขั้นที่ 5

  3. รูปอาหารไม่ขึ้น
     ข้อมูลทดลองไม่ได้ใส่รูป (คอลัมน์ image เป็น NULL)
     ระบบจะแสดงไอคอนแทน ต้องอัปโหลดรูปจริงถึงจะเห็น

  4. การจองหมดอายุช้าสุด 5 นาที
     งานอัตโนมัติเช็คทุก 5 นาที ไม่ได้เช็ควินาทีต่อวินาที
     -> ถ้าอยากเห็นผลทันที กดปุ่ม "ปิดการจองที่หมดอายุ" ในหน้า Admin Web
        หรือยิง POST /api/admin/maintenance/expire-reservations

  5. ไม่มีระบบลืมรหัสผ่าน
     ตัดออกจากขอบเขตแล้ว ถ้าผู้ใช้ลืมรหัส ต้องให้ Admin ตั้งใหม่ให้

  6. ไม่มี Push Notification
     การแจ้งเตือนเก็บในฐานข้อมูล ต้องเปิดหน้าแจ้งเตือนถึงจะเห็น

  7. รีวิวแถวที่ 2 ในข้อมูลทดลองผูกกับการจองที่ยังไม่ completed
     ใส่ไว้เพื่อให้มีข้อมูลโชว์ ในระบบจริง Backend จะไม่ยอมให้เกิดกรณีนี้
