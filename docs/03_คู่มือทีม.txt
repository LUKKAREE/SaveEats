ส่วนที่ 1 : กฎเหล็ก 7 ข้อ - อ่านก่อนเขียนโค้ดบรรทัดแรก
================================================================================

กฎข้อ 1 : Mobile และ Admin Web ห้ามต่อ Database โดยตรง
-------------------------------------------------------
    [ผิด]   Mobile  ->  MySQL
    [ถูก]   Mobile  ->  Backend API  ->  MySQL

    เหตุผล : ถ้าต่อตรง ทุกคนที่มีแอปจะเห็นรหัสผ่าน Database
    ในทางปฏิบัติ : ห้ามติดตั้ง mysql2 ในโปรเจกต์ mobile หรือ admin-web

กฎข้อ 2 : Business Logic ต้องอยู่ที่ backend/src/services/ เท่านั้น
--------------------------------------------------------------------
    สิ่งที่ต้องอยู่ที่ services
        การตัดจำนวนอาหาร
        การตรวจเวลารับ
        การออก QR และรหัส 4 หลัก
        การตรวจสิทธิ์
        การคำนวณระยะทาง
        การคำนวณคะแนนความประพฤติ

    ห้ามเขียนกระจายอยู่ใน UI เด็ดขาด

กฎข้อ 3 : ตรวจสิทธิ์ที่ Backend เสมอ
------------------------------------
    การซ่อนปุ่มใน UI ไม่นับว่าเป็นการรักษาความปลอดภัย
    เพราะใครก็เปิด Postman ยิง API ตรงได้

    ในทางปฏิบัติ : ทุก route ที่ต้องจำกัดสิทธิ์ ต้องมี
        router.get('/xxx', auth, requireRole('admin'), controller.xxx)

กฎข้อ 4 : QR ต้องผ่าน Backend ทุกครั้ง
--------------------------------------
    ห้ามให้แอปตัดสินเองว่า QR ถูกต้องหรือไม่

    [ผิด]  แอปอ่าน QR -> แอปเช็คเองว่าถูก -> แอปบอกว่าผ่าน
    [ถูก]  แอปอ่าน QR -> ส่งไป POST /api/reservations/verify -> Backend ตัดสิน

    เหตุผล : ถ้าให้แอปตัดสิน จะโดนปลอม QR ได้ง่ายมาก และใช้ QR ซ้ำได้

กฎข้อ 5 : หน้าตาข้อมูลประกาศไว้ที่ shared/ ที่เดียว
---------------------------------------------------
    Database  <->  shared/  <->  Backend และ Mobile และ Admin Web

    *** ห้ามประกาศ interface ของข้อมูลซ้ำในแต่ละโปรเจกต์เด็ดขาด ***
    ถ้าต้องการหน้าตาข้อมูลอะไร ให้ import จาก @shared/index

        import type { Post, Reservation, Store } from '@shared/index';

    เดิม (ตอนใช้ JavaScript) กฎข้อนี้เขียนว่า "ตั้งชื่อ field ให้ตรงกันเป๊ะ"
    ซึ่งต้องอาศัยความจำและวินัยของคน
    ตอนนี้ประกาศที่เดียว ถ้าไม่ตรง TypeScript จะฟ้องทันที

    ชื่อ field ใน shared/src/entities.ts ต้องตรงกับคอลัมน์ใน schema.sql เป๊ะ
        Database  : discount_price
        shared    : discount_price
        Backend   : post.discount_price
        Mobile    : post.discount_price

    ถ้าแก้ชื่อคอลัมน์ใน schema.sql ให้ทำแค่ 3 ขั้น
        1. แก้ schema.sql
        2. แก้ shared/src/entities.ts ให้ตรง
        3. รัน npm run typecheck ทั้ง 3 โฟลเดอร์
           แล้วแก้ตามที่ TypeScript ชี้จนหมด error

    *** ห้ามใช้ any และห้ามใช้เครื่องหมาย ! เพื่อปิดปาก TypeScript ***
    ทั้งสองอย่างทำให้เรากลับไปมีปัญหาแบบเดิมของ JavaScript

กฎข้อ 6 : ห้ามเอา .env ขึ้น GitHub
----------------------------------
    ถ้าเพิ่มตัวแปรใหม่ใน .env ต้องไปเพิ่มชื่อตัวแปรใน .env.example ด้วย
    (ใส่แค่ชื่อ ไม่ใส่ค่าจริง)

    ถ้าเผลอ commit ไปแล้ว ต้องเปลี่ยน JWT_SECRET ใหม่ทันที

กฎข้อ 7 : รูปที่ผู้ใช้อัปโหลด ห้ามเก็บใน assets
-----------------------------------------------
    mobile/assets/     = ไฟล์ที่ติดมากับตัวแอปตั้งแต่แรก (logo, ฟอนต์, รูป default)
    backend/uploads/   = ไฟล์ที่ผู้ใช้ส่งเข้าระบบ (รูปอาหาร รูปร้าน รูปโปรไฟล์)

คนที่ 2 : Backend + Database + shared/
--------------------------------------------------------------------------------

      backend/
      database/
      shared/       <-- ดูแล type กลาง ถ้าจะแก้ต้องบอกทั้งทีมก่อน

  งานที่ต้องทำ
      1. ทดสอบ API ทุกเส้นด้วย Thunder Client หรือ Postman (56 เส้น)
      2. เพิ่ม endpoint ที่ยังไม่มี
             PUT    /api/admin/stores/:id/unsuspend ปลดระงับร้าน
             GET    /api/stores/me/stats            สถิติของร้าน

      วิธีทำ : สร้าง hash ด้วย bcrypt แล้ว UPDATE users SET password = '<hash>'

      หมายเหตุ : endpoint 3 ตัวนี้ทำเสร็จแล้ว ไม่ต้องทำซ้ำ
             PUT    /api/auth/me                 แก้ไขข้อมูลส่วนตัว
             PUT    /api/admin/posts/:id/hide    Admin ซ่อนโพสต์
             DELETE /api/admin/reviews/:id       Admin ลบรีวิว

      และงานปิดการจองหมดอายุอัตโนมัติทำแล้วเช่นกัน
             backend/src/jobs/expireReservationsJob.ts  ทำงานทุก 5 นาที
             ใช้ setInterval ของ Node ไม่ได้ลง node-cron เพิ่ม
             (แพ็กเกจน้อย = เพื่อนในทีมติดตั้งง่าย โอกาสพังตอนส่งงานน้อย)

ส่วนที่ 4 : การทำงานร่วมกันผ่าน GitHub

--------------------------------------------------------------------------------
4.1  ตั้ง Repository ครั้งแรก (ทำครั้งเดียว โดยคนใดคนหนึ่ง)
--------------------------------------------------------------------------------

  1. สร้าง Repository ใหม่บน GitHub ตั้งชื่อ SaveEats
     - เลือก Private
     - *** ไม่ต้องติ๊ก Add README / .gitignore / license ***
       (เพราะเรามีอยู่แล้ว จะได้ไม่ชนกัน)

  2. บนคอมของคนที่สร้าง
         cd C:\Users\Admin\OneDrive\Desktop\SaveEats

         git init
         git add .
         git status              <- *** เช็คก่อน commit ทุกครั้ง ***

     *** ก่อนกด commit ให้ดู git status ให้แน่ใจว่า ***
         [ ] ไม่มี node_modules/
         [ ] ไม่มี .env  (ต้องมีแค่ .env.example)
         [ ] ไม่มีไฟล์รูปใน backend/uploads/

     ถ้าเห็นของพวกนี้ แปลว่า .gitignore ยังไม่ทำงาน อย่าเพิ่ง commit

         git commit -m "โครงเริ่มต้นของ SaveEats: database, backend, mobile, admin-web"
         git branch -M main
         git remote add origin https://github.com/<ชื่อ>/SaveEats.git
         git push -u origin main

  3. สร้าง branch develop
         git checkout -b develop
         git push -u origin develop

  4. เชิญเพื่อนเข้า Repository
     Settings -> Collaborators -> Add people

--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
4.4  ขั้นตอนทำงานประจำวัน
--------------------------------------------------------------------------------

  ตอนเริ่มงาน
      git checkout develop
      git pull origin develop
      git checkout -b feature/ชื่องานของคุณ

  ระหว่างทำงาน (commit บ่อย ๆ ดีกว่า commit ทีเดียวก้อนใหญ่)
      npm run typecheck        <-- *** รันก่อน commit ทุกครั้ง ***
      git add .
      git commit -m "เพิ่มหน้าสร้างโพสต์ของร้าน"

  *** ถ้า typecheck ไม่ผ่าน ห้าม commit ***
  เพราะเพื่อนที่ pull ไปจะเจอ error ทันทีและทำงานต่อไม่ได้
  ถ้าเป็น backend ให้รัน npm test ด้วย (ต้องผ่าน 21 ข้อ)

  ตอนจะส่งงาน
      git checkout develop
      git pull origin develop           <- ดึงงานของเพื่อนมาก่อน
      git checkout feature/ชื่องานของคุณ
      git merge develop                 <- แก้ conflict ตรงนี้ถ้ามี
      git push -u origin feature/ชื่องานของคุณ

  แล้วเข้า GitHub เปิด Pull Request จาก feature branch เข้า develop
  ให้เพื่อนกดดูก่อน merge

      ปรับสีปุ่มจองให้ตรงกับธีม

--------------------------------------------------------------------------------

  2. ถ้าต้องแก้ไฟล์กลาง ให้บอกในกลุ่มก่อนเสมอ
     ไฟล์กลางคือ
         shared/src/*.ts                        <-- สำคัญที่สุด กระทบทั้ง 3 ฝั่ง
         mobile/src/core/theme/theme.ts

         database/schema.sql
  3. git pull origin develop ทุกเช้าก่อนเริ่มงาน
  4. อย่าปล่อยให้ branch ตัวเองเก่าเกิน 2-3 วัน

ส่วนที่ 5 : สิ่งที่ต้องทำต่อ (เช็คลิสต์)
================================================================================

--------------------------------------------------------------------------------
5.1  Backend - endpoint ที่ยังไม่มี  (เหลือ 2 เส้น)
--------------------------------------------------------------------------------
  [ ] PUT    /api/admin/stores/:id/unsuspend    ปลดระงับร้าน
  [ ] GET    /api/stores/me/stats               สถิติของร้าน (ยอดขาย จำนวนจอง)

  ทำเสร็จแล้ว ไม่ต้องทำซ้ำ
  [x] PUT    /api/auth/me                       แก้ไขชื่อ เบอร์ รูปโปรไฟล์
  [x] PUT    /api/admin/posts/:id/hide          Admin ซ่อนโพสต์
  [x] DELETE /api/admin/reviews/:id             Admin ลบรีวิว
  [x] POST   /api/reports                       ผู้ใช้แจ้งปัญหา
  [x] GET    /api/reports/my                    เรื่องที่ตัวเองเคยแจ้ง

  ตัดออกจากขอบเขตแล้ว ไม่ต้องทำ
  [-] POST   /api/auth/forgot-password          ตัดระบบลืมรหัสผ่านออกทั้งหมด
  [-] POST   /api/auth/reset-password           ถ้าผู้ใช้ลืมรหัส ให้ Admin ตั้งใหม่ให้

--------------------------------------------------------------------------------
5.2  Backend - ตัวจับเวลาปิดการจองหมดอายุ (ข้อค้าง 6)  -> ทำเสร็จแล้ว
--------------------------------------------------------------------------------
  ไฟล์ : backend/src/jobs/expireReservationsJob.ts
  เรียกใช้ : backend/server.ts (หลังเชื่อมฐานข้อมูลสำเร็จ)
  ความถี่ : ทุก 5 นาที

  *** ทำไมใช้ setInterval ไม่ใช้ node-cron ***
  setInterval มากับ Node อยู่แล้ว ไม่ต้องลงแพ็กเกจเพิ่ม
  แพ็กเกจยิ่งน้อย เพื่อนในทีมยิ่งติดตั้งง่าย โอกาสพังตอนส่งงานยิ่งน้อย
  งานระดับ "เช็คทุก 5 นาที" ไม่ต้องใช้ความสามารถของ cron เลย

  สิ่งที่โค้ดกันไว้ให้แล้ว
      - ตัวแปร running กันไม่ให้รอบใหม่เริ่มทับรอบเก่าที่ยังไม่เสร็จ
      - try/catch ครอบไว้ ถ้าฐานข้อมูลล่มชั่วคราว server ไม่ตายตาม
      - timer.unref() ทำให้กด Ctrl+C แล้วปิดได้ทันที ไม่ต้องรอครบรอบ
      - รันทันที 1 รอบตอนเปิด server เผื่อปิดไปนานแล้วมีของค้างเยอะ

  ยังมีปุ่มกดเรียกเองอยู่ที่หน้า "การจอง" ใน Admin Web
  ไว้ใช้ตอนทดสอบ จะได้ไม่ต้องนั่งรอครบ 5 นาที

    import LoadingView from '../../../components/LoadingView';
    import EmptyState from '../../../components/EmptyState';

    // ระบุชื่อหน้าจอ -> TypeScript จะรู้เองว่า route.params มีอะไรบ้าง
    type Props = CustomerScreenProps<'PostDetail'>;

    export default function PostDetailScreen({ route }: Props): JSX.Element {
      const { postId } = route.params;   // <- รู้เลยว่าเป็น number

      const [data, setData] = useState<FeedItem | null>(null);
      const [loading, setLoading] = useState(true);
      const [error, setError] = useState<string | null>(null);

      useEffect(() => {
        void (async () => {
          try {
            setData(await feedService.getPost(postId));
          } catch (err) {
            setError(errorMessage(err));   // err เป็นชนิด unknown ต้องแปลงก่อน
          } finally {
            setLoading(false);
          }
        })();
      }, [postId]);

      if (loading) return <LoadingView />;
      if (error !== null) return <EmptyState title="โหลดข้อมูลไม่สำเร็จ" message={error} />;
      if (data === null) return <EmptyState title="ไม่พบข้อมูล" />;

      // ตรงนี้ TypeScript มั่นใจแล้วว่า data ไม่ใช่ null
      return <Text>{data.food_name}</Text>;
    }

    async function pickImage(): Promise<PickedImage | null> {
      const result = await ImagePicker.launchImageLibraryAsync({
        mediaTypes: ImagePicker.MediaTypeOptions.Images,
        quality: 0.7,
      });
      if (result.canceled) return null;

      const asset = result.assets[0];
      if (asset === undefined) return null;

      return {
        uri: asset.uri,
        name: asset.fileName ?? 'photo.jpg',
        type: asset.mimeType ?? 'image/jpeg',
      };
    }

      }

      return (
        <CameraView

          barcodeScannerSettings={{ barcodeTypes: ['qr'] }}
          onBarcodeScanned={scanned ? undefined : ({ data }) => { void handleScan(data); }}

    import { useCallback, useEffect, useState } from 'react';
    import type { Report } from '@shared/index';

    export default function ReportListPage(): JSX.Element {
      const [rows, setRows] = useState<Report[]>([]);
      const [loading, setLoading] = useState(true);
      const [error, setError] = useState('');
